# 운영 판단 모델 v2 개선 결과 — 2026-10-01

실제 실행 로그 형식을 학습에 보강하고 정규화·균형 학습을 적용한 LoRA 모델에서, 새로 분리한 동일 평가 자료의 정확도가 v1 1/71(1.4%)에서 v2 71/71(100%)로 개선됐다. 기존 40.9%는 다른 자료에서 얻은 수치이므로 새 평가의 100%와 직접 비교하지 않는다. 이 결과는 운영 상태 분류의 개선이며 논문용 고장 탐지 성능과 별개다.

## 적용한 방법

1. **실패 원인에 맞춘 실제 자료 보강**: v1 학습에 없던 live status 입력을 추가했다. 이미 분석한 기존 test는 개발·학습 자료로 명시적으로 재사용했다. 실제 DB 작업 생명주기에서 관측된 상태도 추가했다. 학습 69건·12그룹, 검증 20건·3그룹이다.
2. **입력 정규화**: 상태·단계·epoch 등 관측 사실을 보존하고 작업 이름·경로·시각 같은 식별자는 제외했다. 정답 행동을 입력에 넣거나 없는 상태를 생성하지 않았다. 학습과 추론이 동일한 변환을 사용한다.
3. **그룹 및 클래스 불균형 완화**: 반복 epoch가 많은 실행이 학습을 독점하지 않도록 실행 그룹별 샘플링 질량을 맞췄다. 행동별 독립 그룹 수의 역제곱근으로 손실 가중치를 조정했다.
4. **학습과 모델 선택 개선**: Qwen2.5-0.5B-Instruct에 rank 8 LoRA 및 분류 head를 실제 학습했다. LoRA 학습률 0.0002, head 학습률 0.001, gradient clipping 1.0, 최소 3·최대 8 epoch, patience 2를 사용했다. 검증 macro-F1을 우선하고 동률이면 검증 손실로 선택했다.
5. **누출 방지**: 두 후보의 검증 평가가 끝난 뒤 모델·코드·데이터 해시를 고정했다. 그 후 main 실험의 상태와 게시된 최종 결과만 한 번 추출하여 두 모델에 같은 입력을 제공했다. 테스트를 보고 학습 설정을 바꾸지 않았다.

## 두 학습 조건 비교

| 조건 | 실행 / 선택 epoch | 검증 정확도 | 검증 손실 | CPU 시간 |
|---|---:|---:|---:|---:|
| 실제 로그 보강 + 원문 입력 | 3 / 1 | 20/20 (100%) | 0.0254485 | 172.5초 |
| 실제 로그 보강 + 정규화 + 균형 학습 | 6 / 4 | 20/20 (100%) | 0.0000002265 | 213.8초 |

검증 macro-F1은 두 조건 모두 등장한 2개 행동 기준 1.0, 전체 5개 행동 기준 0.4다. 미리 정한 손실 기준으로 두 번째 조건을 선택했다. 두 조건의 정확도는 같으므로 정규화나 균형 학습 각각이 정확도를 올렸다고 분리해서 주장할 수 없다. 모델 확률은 보정되지 않았으며 낮은 검증 손실이 실제 운영의 신뢰도를 보증하지 않는다.

## 새 평가 자료에서 동일 조건 비교

| 모델·기준선 | 정답 / 전체 | 정확도 | 등장한 2개 행동 macro-F1 |
|---|---:|---:|---:|
| 기존 v1 | 1/71 | 1.4% | 0.0139 |
| 선택된 v2 | 71/71 | 100% | 1.0000 |
| 학습 최빈 행동만 출력 | 70/71 | 98.6% | 0.4965 |
| 관측 상태의 명시적 규칙 | 71/71 | 100% | 1.0000 |

실행 중 상태 70건에서 v1은 전부 틀렸고 v2는 전부 맞혔다. 게시된 완료 결과 1건은 양쪽 모두 맞혔다. 전체 5개 행동 macro-F1은 v1 0.00556, v2 0.4다. 미검증 행동의 F1을 0으로 두는 정의다.

71건은 **하나의 실행 그룹**에서 나온 상관된 기록이며, 대부분 같은 행동이다. holdout 지정은 main 실행 시작 및 통상적인 상태 확인 이후, v2 데이터 추출 이전에 했다. 완전히 새롭고 독립적인 71개 실험이 아니다. 정답은 운영 규칙으로 정했고 사람의 독립적인 판단 정답이 아니므로, 단순 규칙보다 우수한 판단 능력을 입증한 것도 아니다.

## 기존 자료의 개발 회귀 확인과 남은 오류

기존 22건에서는 v1 9/22(40.9%) → v2 21/22(95.5%)였다. 이 자료는 v2 학습에 사용했으므로 일반화 성능으로 제시하지 않는다.

남은 오류는 실제 PARTIAL 상태를 RESUME_INCOMPLETE 대신 MONITOR_RUNNING으로 판단한 1건이다. 틀린 판단의 모델 확률도 98.18%였으므로 확률 임계값만으로 안전하게 자동화할 수 없다. 해당 입력과 모델 판단을 HUMAN_REVIEW_QUEUE.json 및 DB에 보존했다. human_label은 null이며 사람이 검토했다는 승인을 만들지 않았다.

다음 개선은 독립적인 실제 중단·재개·실패 사례와 사람이 판단한 모호한 사례를 수집하고, 새로운 실행 그룹으로 다시 평가하는 것이다. REQUIRE_HUMAN_REVIEW는 학습 사례가 없고 실패·재개 사례도 충분하지 않다. 현재 모델은 여전히 제안용이며 자동 실행 권한은 없다. 새 holdout은 이후 개발에 쓰더라도 더 이상 미사용 평가 자료로 부르지 않는다.

## 구현·운영 확인

- 기존 v1 가중치는 원래 보고서 해시와 동일하다. v2 가중치는 실제 변경됐다.
- 선택된 어댑터: `outputs/harness/models/chum-ops-v2-balanced`. 선택 및 해시는 MODEL_SELECTION.json에 보관한다. 가중치는 Git에서 제외한다.
- 기존 `harness route`에 선택된 어댑터를 지정해 실제 추론과 SQLite 기록까지 확인했다. INFERENCE_DEMO.json 참조. 기본 v1 경로를 조용히 바꾸지 않았으므로 사용 시 CHUM_FINETUNED_ADAPTER를 지정한다.
- paired 평가와 검토 요청은 DB 이벤트 548·549에 기록했다. 학습 epoch도 DB에 기록된다. 학습 자료와 모델 평가 출력은 RAG 근거 색인에서 제외된다.
- 전체 테스트 127개 통과 후, 마지막 평가 동결 보완을 포함한 관련 테스트 28개가 통과했다.
- 고장 탐지 main 실험은 GPU에서 계속 진행하고, 이번 모델 학습·추론은 CPU에서 수행했다.

수치의 원본은 COVERAGE_REPORT.json, BALANCED_REPORT.json, HELDOUT_EVALUATION.json, DEVELOPMENT_REGRESSION.json이다. 전처리·표본 구성·평가를 독립 에이전트가 검토했다.
