# CHUM 연구 확장: 실행 순서와 이유

갱신: 2026-09-21
사용자 지시: 검증·집필 반복을 중단하고, 탐지 성능과 논문 기여를 높이는 실제 실험을 진행한다. 아래 순서를 정한 이유를 다음 세션에서도 유지한다.

## 목표와 우선순위

CHUM의 조건부 제어 이력 유용성 발견을 실제 탐지 성능 개선으로 연결한다. 학습 seed만 늘려 반복성을 확인하는 일보다 학습 조건 개선, 채널 선택의 실용성, 적응적 제어 결합의 필요성을 순서대로 실험한다.

| 순서 | 할 일 | 이 순서인 이유 | 다음 단계의 판단 근거 |
|---|---|---|---|
| 1 | 충분히 학습한 기준 모델, window, 이상 점수 개선 | 덜 학습된 기준 모델과 비교하면 새로운 방법의 이득을 과대평가할 수 있음 | 정상 validation에서 선택한 checkpoint와 같은 오경보 기준의 탐지 성능 |
| 2 | CHUM 선택 채널로 재학습; 전체 채널·무작위·다른 선택법 비교 | 복잡한 새 구조 전에 기존 utility 분석이 실제로 유용한지 확인 | 미사용 평가 데이터에서 입력 수 대비 탐지 성능 개선 또는 유지 |
| 3 | 채널·시간 선택을 학습하는 제어 결합 모델 | 고정 채널 선택의 한계가 확인돼야 적응 구조의 필요성을 주장할 수 있음 | 같은 예산의 고정 결합보다 성능·오염 강건성 개선 |
| 4 | 가까운 탐지·설명 방법과 직접 비교 | 단순 ablation만으로 경쟁력·신규성이 입증되지 않음 | 동일 split·튜닝 예산·공통 지표에서 차별점 확인 |
| 5 | 미사용 run, 새로운 운전 조건, 외부 데이터 | 같은 TEP test에 맞춘 개발 효과를 일반화로 오해하지 않기 위함 | 조건 변화·다른 데이터에서도 개선 유지 |

## 현재 실행: 1A 학습 길이

- TCN / Transformer, F0 / F1 / F0-C, seed 47: 총 6개 모델.
- 기존 window=20, hidden=32, layers=2, Adam lr=0.001, batch=1024, split/scaler 유지.
- 처음부터 학습: epoch 10 checkpoint와 정상 validation 최적 checkpoint를 보존.
- 최대 50 epochs, 최소 10 epochs, patience=7, min_delta=0.0001 (validation MSE의 절대 개선량).
- 매 epoch 정상 validation MSE만으로 checkpoint 선택. test label·test metric은 학습 종료나 선택에 사용하지 않음.
- 절대 최저 validation MSE의 가중치를 복원한 후 한 번 test 평가.
- 기존 seed47의 10 epoch 결과는 비교 기준. 같은 seed·split 비교는 개발 실험이며 새로운 독립 데이터셋 검증이 아님.
- Transformer F0와 F0-C는 기존 폭 매칭에서 동일 구조임을 유지·공개. 서로 독립적인 모델 구조로 세지 않음.
- 정상 예측 MSE 개선이 탐지 성능 개선을 보장하지 않음. AUROC/AUPRC뿐 아니라 FPR, 탐지율, 미탐지, 지연을 함께 기록.

## 다음 1B·1C

학습 길이 결과를 해석한 뒤 window 60/120 및 잔차 점수 설계를 비교한다. 현재 Transformer position은 길이 20으로 고정돼 있고 TCN receptive field도 짧다. window 숫자만 바꾸지 말고 실제 입력을 활용하도록 구조를 조정하며, 그에 따른 용량 변화는 별도 대조한다.

한 축씩 바꾼다. 동일 평가 run·sample 범위를 사용한다. 큰 모델·diffusion·foundation model 추가를 개선이라고 가정하지 않는다.

## 데이터 사용 경계

기존 test는 이미 반복 관찰되었으므로 이후 방법 개발에서는 개발 벤치마크로 취급한다. 새 방법의 최종 일반화 주장에는 실제로 미사용한 run/외부 데이터가 필요하다. 기존 test에서 골랐던 네 셀을 그대로 사용한 성능을 독립적인 채널 선택 일반화로 주장하지 않는다. 새 split만 섞는다고 이미 본 데이터를 미사용 데이터라고 부르지 않는다.

채널·시간 gate는 추론 시 과거 관측만 사용하고 정답 fault ID나 미래 관측을 받지 않는다. 가중치를 물리적 원인으로 해석하지 않는다. HAI의 직접 공격 control에서 얻은 효과를 비공격 제어 이력 전체로 일반화하지 않는다.

## 변경 원칙

순서를 바꿀 때는 관찰된 실험 결과, 바꾸는 이유, 새 비교 기준을 이 문서에 추가한다. 효과가 없으면 그대로 기록하고 다음 설계 판단에 사용한다. 지도교수 승인·논문 최종 제출 완료를 추정하지 않는다.
